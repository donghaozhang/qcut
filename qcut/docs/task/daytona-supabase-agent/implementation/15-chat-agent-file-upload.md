# Chat Agent File Upload and Virtual Folder

Date: 2026-05-17

## Goal

Make `https://quriosity.com.au/chat-agent.html` support user file and image uploads into the Daytona sandbox, expose uploaded and generated files in one virtual folder, and let the user download files from the page.

## Implemented

- Added a Chat Agent upload control in `packages/nexusai-website/chat-agent.html`.
- Added multipart upload support in `packages/nexusai-website/js/agent-chat.js`.
- Added the first virtual sandbox file browser backed by:
  - `/tmp/qcut-input` for user uploads.
  - `/tmp/qcut-output` for files generated by Codex or QCut CLI.
- Upgraded the browser to a full active-sandbox filesystem explorer:
  - The UI starts at `/`.
  - Users can click folders to enter them.
  - Users can jump back to root or move up one folder.
  - Uploads go to the currently selected sandbox folder.
  - Files can be downloaded by full sandbox path.
- Added frontend download routing for both uploaded input files and generated output files.
- Updated the Codex website agent prompt and relay startup instructions so Codex knows uploaded files are under `/tmp/qcut-input`.
- Updated the Daytona PTY startup command to create `/tmp/qcut-input`, `/tmp/qcut-output`, and `/tmp/qcut-tools`.
- Updated the QCut CLI default output policy so `QCUT_OUTPUT_DIR=/tmp/qcut-output` becomes the default output directory inside the website sandbox, while desktop users still fall back to `~/Documents/QCut/exports` when the env var is unset.
- Added license-server API routes:
  - `GET /api/agent/sessions/:sessionId/files`
  - `POST /api/agent/sessions/:sessionId/files`
  - `GET /api/agent/sessions/:sessionId/files/download?path=/absolute/sandbox/path`
  - `GET /api/agent/sessions/:sessionId/files/:folder/:filename/download`
- Extended `GET /files` and `POST /files` with `?path=/absolute/sandbox/folder`.
- Kept the old input/output routes working for compatibility.
- Added path normalization so sandbox filesystem routes accept absolute paths and reject traversal such as `..`, backslashes, and null bytes.
- Fixed multipart parsing to use `parseBody({ all: true })`; the first live E2E found that default parsing only kept the last file when multiple files used the same form field.
- Deployed updated Workers:
  - `qcut-license-server` version `b831fc20-e03e-4a12-b28c-809cd7f56a2c`
  - `qcut-relay` version `e490005e-c4a4-4c3d-88e0-3a31b7da6f55`
- Pushed website commit `c2f5cf3` to `nexusai-website/master`.
