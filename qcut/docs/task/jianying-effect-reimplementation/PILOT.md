# 复刻试点:用参照库把剪映特效做成 QCut 自研特效

日期:2026-08-17 · 分支:effects-v2 · 状态:**试点完成,4 个特效,3 上架 1 撤回**

参照库([jianying-effect-reference-line](../jianying-effect-reference-line/README.md))
攒了 700+ 条参照,但一个都没被用来复刻过。本试点的目的**不是多做几个特效**,
而是把复刻这条流水线走通一次,回答三个问题:验收标准是什么、一个特效多久、
参照缺什么。

## 结果

| 特效 | 原语 | 验收 | 结论 |
|---|---|---|---|
| 电影感画幅 `basic-cinema-bars` | decoration(新增 letterbox 变体) | 条高 132px,全 180 帧偏差 ≤1px(门槛 ±2px) | **上架** |
| 渐显开幕 `basic-fade-open` | motion + **首次使用 render window** | 增益曲线 rms 0.0320(≤0.05)、max 0.0635(≤0.08) | **上架** |
| 雾气 `nature-mist` | particles(fog) | 符号纯度/覆盖量/色相通过,**结构度 2.07x 未过** | **上架**(带已知差异) |
| 孔明灯 | particles(embers) | 覆盖量仅参照的 **2%** | **撤回** |

## 一、验收标准:感知/统计级,不是像素级

**这个结论是量出来的,不是拍的。** 参照片相邻帧运动量 10.66/255,候选错一帧
就让逐像素 MAD 上涨 6.6,而编解码噪声底只有 1.385。也就是说像素判据被**对齐
误差**主导而不是被特效主导:严了会误杀正确实现,松到能容忍漂移又会放过错误
实现。改用**每帧拟合标量**后,同样错一帧只影响 1.73%,低于可达保真差距
3.27%,判据才真正有分辨力。

**不要复用滤镜 LUT 那套阈值**(rgbRmse ≤ 1 / ssim ≥ 0.995)。那是同一帧上
两个确定性函数的对拍,本场景根本达不到。

### A 层:确定性特效

- **几何类**(电影感画幅):条位置逐帧检测,±2px。±2 是吸收编解码振铃——
  参照自己在 f90/f135 也抖 1 行。另加未受影响区域 MAD ≤ 3.0(噪声底的 2 倍)。
- **一次性动画**(渐显开幕):逐帧最小二乘增益 `g(t)=Σ(plate·clip)/Σ(plate²)`,
  rms ≤ 0.05、max ≤ 0.08。**阈值是推导出来的**:`1-cos` 逼近剪映的 ≈x²,可达
  rms 0.0327 + 一帧漂移 0.017;同时比错误形状(线性 rms 0.181、smoothstep
  0.190)紧 5.5 倍,所以它真的能区分对错。外加免费的端点门:g(0) ≤ 0.02、
  窗口后均值 ≥ 0.99。

### B 层:随机性特效(粒子)

不存在逐像素目标——QCut 的粒子场是同一种观感的**另一次随机实现**。改为对
**加性光照图 `D = clip − plate`** 卡四项分布统计:

1. **符号纯度**:被压暗超过 25 的像素占比 ≤ 0.002。最强也最便宜的一道门,
   混合模式错了立刻暴露。
2. **覆盖量**:mean|D| 在参照的 ±25% 内。
3. **结构度**:空间 std/mean 比在 ±30% 内。区分"有结构的场"和"一层平雾"。
4. **色相**:加性 RGB 方向夹角 ≤ 10°。

## 二、一个特效要多久

**四个特效 20 分钟**(含类型检查、测试、格式化、三次调参迭代)。但这个数字
要正确解读:

- **实现本身很便宜**。两个 A 层特效各是"填空题"——纯数据或一个 20 行绘制函数。
- **贵的是前面的机制测量**。是"条高 132px""增益曲线形状 ≈x²""fog 变体的
  blob 尺度与漂移速率匹配"这些**量出来的数字**把实现变成了填空。没有这一步,
  就是凭感觉调参。
- **调参迭代 40 秒一轮**。雾气色相从 13.1° 降到 5.2° 用了三轮。这个循环足够快,
  可以真正做拟合而不是猜。

所以真实成本模型是 **测量 + 实现**,而测量可以批量并行做。

## 三、参照缺什么(最有价值的部分)

1. **参照片选错了**。它是动态镜头,自带 10.66/255 的帧间运动,直接毁掉了像素
   级判据。**应该同时渲一版静止片源**(冻结一帧),运动混淆归零后 A 层判据能
   收紧到接近噪声底。这是参照库该补的第一件事。
2. **610 条参照里有 70 条的中文名与 Gen-1 现有条目完全相同**——暗角、开幕、
   放大镜、轻微抖动等都已实现过。参照库必须**先去重再排优先级**,否则重复劳动。
3. **参照只有"最终画面",没有中间量**。雾气的结构度对不上,但从视频里无法
   区分是"粒子数不对"还是"单颗尺寸不对"——两者产生相同的 mean|D|。若参照能
   附带分层(纯特效层 / 掩码),拟合会从猜测变成解方程。

## 四、顺带发现的原语边界

- **`EffectRenderWindow` 此前零使用**。它在所有 stage 类型上都有、导出侧也已
  实现,但 166 个条目一个都没用过。渐显开幕是第一个——**一次性动画(开幕、
  闭幕、冲击)这一整类此前无法正确表达**,没有窗口的余弦通道会在片中途自己
  淡回去。
- **粒子没有尺寸旋钮**。孔明灯的方向、颜色、加性全部匹配 `embers`,唯独尺寸
  硬编码在 0.004–0.012,导致灯笼渲成火星、覆盖量只有 2%。这是一个**具体、
  小、有明确收益**的原语改动,做完可解锁"大颗粒上升物"这一类。
- **粒子只有一个颜色**。`{color}` 是单值,彩带类特效的多色场无法表达。
- **`EffectPreset` 没有 `animations` 字段**(关键帧只存在于 `EffectInstance`),
  所以"关键帧化的强度"那一整类(约 31 条参照)不能作为纯目录数据表达。

## 五、上架政策(试点确立)

**未通过验收的条目不上架。** 孔明灯被撤回并在代码里注明原因和解锁条件。
理由很直接:如果允许"差不多就发",验收标准就失去意义,而参照库的全部价值
正是建立在"我们能判断像不像"之上。

带**已知差异**上架是可以的(雾气结构度 2.07x),前提是差异被测量、被记录、
且不属于该特效的核心特征——雾气的核心是"冷白加性雾",结构度差异表现为雾块
比参照更碎,可接受;而孔明灯的核心就是"大而暖的灯笼",尺寸不对等于没做。

## 复现方式

验收脚本在会话 scratchpad(未进仓库,因为它依赖 gitignored 的参照库):
A 层用 `verify-pilot.ts`(纯 ffmpeg + 数学),B 层用 `verify-particles.mjs`
(`@napi-rs/canvas` 跑**仓库自己的** `drawParticleStageFrame`,测的是产品代码
而不是脚本里的复述)。要长期化的话,应该做成 `scripts/` 下的工具并接受
参照库路径作为参数。
