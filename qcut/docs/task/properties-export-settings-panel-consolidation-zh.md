# 属性 / 导出 / 设置面板整合方案

## 现状

右侧栏由 `PanelTabs` 管理，包含 **3 个标签页**：

| 标签页 | 内容 | 文件 |
|--------|------|------|
| **Properties（属性）** | 元素专属控件（文本、媒体、音频、markdown、remotion、变换、特效）。未选中元素时显示项目信息（名称、宽高比、分辨率、帧率） | `properties-panel/index.tsx`（227 行） |
| **Export（导出）** | 完整导出流程——预设、文件名、画质、引擎、格式、详细参数、字幕、音频 | `export-dialog/export-dialog.tsx` + 子组件 |
| **Settings（设置）** | 3 个子标签：项目信息、背景、API 密钥 | `properties-panel/settings-view.tsx`（742 行） |

### 设置子标签详情

| 子标签 | 内容 | 行数（约） |
|--------|------|------------|
| 项目信息 | 名称、宽高比、帧率下拉框 | 90–167 |
| 背景 | 模糊预览（3 级）、颜色网格 + 取色器 | 169–295 |
| API 密钥 | 5 个密钥输入框，含显示/隐藏、测试按钮、保存、来源标识 | 297–741 |

## 存在的问题

### 1. 项目信息重复
项目信息出现在 **两个地方**：
- 属性标签页空状态（`index.tsx` 第 67–114 行）——显示名称、宽高比、分辨率、帧率
- 设置 > 项目信息子标签（`settings-view.tsx` 第 90–167 行）——显示名称、宽高比、帧率

属性空状态中的宽高比/分辨率是只读的，设置中的版本才是可编辑的下拉框。用户可能不知道需要去设置页才能修改在属性页看到的数值。

### 2. API 密钥不应放在面板标签中
API 密钥是 **一次性配置** 任务。作为常驻子标签与项目设置并列，浪费空间且增加认知负担。它们占了 `settings-view.tsx` 约 60% 的代码量。

### 3. settings-view.tsx 接近 800 行上限
目前 742 行，任何新增内容都会超限。文件混合了三个无关的功能。

### 4. 背景设置位置不合理
背景模糊/颜色是项目画布的视觉属性，却放在"设置"标签下，与画布预览割裂。

---

## 方案：整合为 2 个标签 + 1 个弹窗

### 标签 1：Properties 属性（保留并增强）

将项目信息和背景合并到属性标签页的空状态中：

```text
属性标签（未选中元素时）：
├── 项目信息（可折叠，可编辑）
│   ├── 名称
│   ├── 宽高比（下拉框）
│   ├── 分辨率（显示）
│   └── 帧率（下拉框）
└── 背景（可折叠）
    ├── 模糊（3 级）
    └── 颜色（网格 + 取色器）

属性标签（选中元素时）：
├── 元素专属控件（不变）
└── 变换/特效（不变）
```

**原因**：项目信息和背景都属于"画布级属性"。未选中元素时，属性面板应展示画布本身的所有设置。这样消除了重复，也让背景设置更容易被发现。

### 标签 2：Export 导出（保持不变）

不做修改。导出是一个完整的独立流程，有自己的预设、画质、格式和进度追踪，适合作为专属标签页。

### API 密钥：移至弹窗对话框

将 API 密钥提取为独立弹窗，可通过以下方式打开：
- 顶部菜单栏（设置 > API 密钥）
- 属性面板底部的齿轮图标/按钮

**原因**：API 密钥配置一次后很少再访问。弹窗是凭证管理的标准 UX 模式（VS Code、Figma 等均如此）。

---

## 备选方案：保留 3 个标签，仅重新组织

如果移除设置标签太激进：

| 标签 | 内容 |
|------|------|
| Properties 属性 | 元素属性 + 未选中时显示项目信息/背景 |
| Export 导出 | 不变 |
| Settings 设置 | 仅保留 API 密钥（可将标签重命名为"API Keys"或保留"Settings"） |

这样仍能消除项目信息的重复，并将背景移到更合理的位置。
