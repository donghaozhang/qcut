# 逐字版式缺口 / The per-letter typography gap

日期 / Date: 2026-08-17 · 分支 / branch: `effects-v2`

## 缘起 / Why this exists

字幕池复核时,约 19–30 个包被我按**名字**判为"不是动画,是排版样式,
属另一个系统"(下划线、大字报、拼贴、多行排版…)。这是整轮工作里唯一
一个**只凭名字、从未打开过包**的判断。逐包查证后它站不住。

## 实况 / What they actually are

| 包 | charWrites | 内容 |
|---|---|---|
| 不规则 / 不规则大字报 | 31 | 按行分配 fontSize 倍数(2.5× / 1.8× / 1.2×)+ 逐字母绝对定位 |
| 大字报混剪 | 30 | 同族 |
| 不规则弯曲 | 20 | 同族 + 弯曲基线 |
| 多行排版 / 多行排版 II | 17 / 14 | 分行版式 + 逐字定位 |
| 基础大字报 | 13 | 同族 |
| emoji多样式组合 | 10 | 清单 3637 个文件(素材库) |
| 下划线 I/II/III、冰雪飘动、左滑、上滑、双行线条、复古拼贴、多行变焦 | 4–5 | 轻量逐字 |

**比我们移植过的绝大多数都高** —— 当初的头号目标 逐字旋出 才 28。
所以"不是动画"这句话是错的。全部由词钟(`c_module` / `textTimeData`)
驱动。

## 但它们确实不属于文字动画线 / Why they still don't fit

读进代码看,这些包做的是**版式生成**而非变换叠加:

```
letter.letterStyle.fontSize = oriLetter.letterStyle.fontSize * 2.5
letter.position = Amaz.Vector2f(lineCenter.x - 140, ... )
```

字号被重新决定、每个字被绝对摆放 —— 行宽、换行、落点全部随之改变。

QCut 的文字动画层在**布局之后**施加逐单元变换(平移/缩放/旋转/
透明度)。`scaleX` 放大一个字**不会推开邻居**,行也不会重排。要复刻
大字报,需要的是**逐单元字号进入排版计算**,那是文本布局层的能力,
不是动画层的能力。

## 更正后的判定 / Corrected verdict

- ❌ 原判"不是动画,是样式" —— 错,它们有大量逐字数学
- ✅ 准确:**逐字版式生成;动画层运行在布局之后,表达不了会改变布局
  的变换**

## 价值与规模 / Why it's worth scheduling

这不是"另一个系统的琐事",是一个之前没识别出来的**真实能力缺口**,
且有独立产品价值:"大字报 / 绑架信"式排版在短视频里很常见,远不止
这 19 个包。

做的话触及文本布局(`buildTextAnimationCanvasLayout` 与其上游的度量、
换行、行宽计算),比 raster pass / 多 selector / GPU shader 这三项都
大,应单独立项而不是塞进当前这条线。

**先决条件**:布局层支持逐单元 fontSize(影响 advance 与换行),之后
动画层才谈得上在其上叠加变换。

## 教训 / Method note

这是本轮第六次同类失误:**用一个不适用的依据下结论**。前五次是拿
Lua 家族的 charWrites 去量 lsanim 家族、漏看词钟信号、误称 bloom 无
消费者、把"我没抽到文件"当成"文件加密"、把可行性上限当实际产出。
这一次是拿名字当依据。

统一的纠正办法:**任何"不做"的判定必须写明依据,且依据必须是打开过
的东西** —— 名字、指标零值、清单缺失都不算。
