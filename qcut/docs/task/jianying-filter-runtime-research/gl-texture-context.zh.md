# GL 纹理上下文对齐

记录时间：2026-08-09，2026-08-10 追加中文剪映 UI、ProRes 和无缩放对照

## 问题定位

最初的 EGL/GLES 探针可以创建 Effect handle、初始化运行时并加载 Effect 包，但目标纹理没有得到有效画面。输出日志显示输入 2D 纹理不可加载，运行时改用零纹理。

符号绑定检查给出了直接原因：目标 Effect 库的 `_glBindTexture`、`_glIsTexture`、`_glTexImage2D`、`_glFramebufferTexture2D` 和 `_glReadPixels` 均来自 macOS `OpenGL.framework`，而探针的纹理来自另一套 EGL/GLES context。相同的整数纹理 ID 不代表相同的 GPU 对象。

## 验证矩阵

| 图形路径 | GL 版本 | 纹理可见 | Shader | 目标纹理 |
| --- | --- | --- | --- | --- |
| 缓存 EGL/GLES3 | OpenGL ES 3 | 否 | 可进入处理 | 保持测试种子 |
| CGL legacy | OpenGL 2.1 Metal | 是 | GLSL 330 编译失败 | 黑帧 |
| CGL 3.2 core | OpenGL 4.1 Metal | 是 | 成功 | 有效滤镜输出 |

这表明“同 context”是必要条件，但不是充分条件。context profile 还必须满足运行时生成的桌面 GLSL 版本。

## 工作调用顺序

```text
创建 CGL 3.2 core context
  -> CGLSetCurrentContext
  -> 用 OpenGL.framework 创建 sourceTexture
  -> 用 OpenGL.framework 创建 targetTexture
  -> 创建 Effect handle
  -> 执行正式 SDK 所要求的授权步骤
  -> 设置 render API
  -> init(width, height, modelDirectory)
  -> set_width_height(width, height)
  -> set_orientation(orientation)
  -> set_effect(effectPackageDirectory)
  -> 每帧 algorithm_texture(sourceTexture, timestamp)
  -> 每帧 process_texture(sourceTexture, targetTexture, timestamp)
  -> targetTexture 挂载同一 context 的 framebuffer
  -> glReadPixels 验证
  -> 销毁 handle、纹理和 context
```

必须保持以下不变量：

1. source 和 target 是两张独立、同尺寸的 `GL_TEXTURE_2D`。
2. 纹理创建、SDK 初始化、素材加载、算法、渲染和读回使用同一个 current context。
3. 上述生命周期位于同一个线程。
4. 每次 SDK 调用后检查 context、`glIsTexture` 和 `glGetError`。
5. 不能只根据接口返回零判定成功，必须读回并比较目标像素。

### 真人图片验证

使用仓库已有、可用于 QCut 预览的真人肖像图，裁剪为 512x512 P6 PPM。画面同时包含前景人物的脸、颈部、肩膀、双臂和复杂背景，可以检查 mask 方向与边界。

为避免只凭成品图判断，在仓库外的临时 Effect 包副本上分别读回四种结果：

1. 原始效果的双 LUT 混合输出；
2. 只输出背景 `LUT0`；
3. 只输出皮肤 `LUT1`；
4. 将实际 `mask.a` 直接输出为灰度图。

所有运行均使用同一 CGL 3.2 core context、同一输入纹理和 20 帧预热。第一帧等待异步模型时算法返回 `-11`，第 2 至 20 帧的算法和效果处理都返回 `0`；读回时 framebuffer 完整，GL error 为 `0`。

验证结果：

- 直接读回的 skin mask 与前景人物的脸、颈肩和双臂空间对齐；它也标出了背景人物暴露的皮肤，这符合 skin segmentation 而非单人 instance mask 的语义。
- 完整效果与 `LUT0` 的绝对差图与 mask 位置一致；全图 mask 强度与绝对 LUT 差值的 Pearson 相关系数为 `0.9334`。
- 跳过算法时的输出与直接输出 `LUT0` 逐字节相同，证明缺少 mask 时回落到背景 LUT。
- 用读回结果在 CPU 上重建 `LUT0 * (1 - mask) + LUT1 * mask`，与原始双 LUT 效果比较：每通道 MAE `0.303162`，`92.7467%` 的通道误差不超过 1，`99.3656%` 不超过 2，最大误差 7，PSNR `51.316 dB`。剩余差异符合将中间浮点结果分别量化为 8-bit 后再重建的误差。

因此，本次已确认该人像效果在当前本机运行时中执行了真实的 skin segmentation，并使用 mask alpha 在背景 LUT 和皮肤 LUT 之间做逐像素混合。测试图、临时 Effect 副本、原始日志和输出图仅保留在仓库外，不进入 Git。

## 中文剪映 UI 同素材逐帧对照

### 对照设置

本次使用中文剪映专业版 `com.lemon.lvpro`，应用版本 `11.1.12988`、构建版本 `11.2.0-beta7`。在一次性草稿中通过滤镜卡片的轨道添加入口应用“相机模拟 / 奥林巴斯”，而不是只点击卡片进行临时预览。验证截图同时包含以下自证信息：

- 独立紫色滤镜轨道覆盖完整 6 秒素材；
- 右侧滤镜参数显示名称“奥林巴斯”；
- 强度显示 `100`。

同一草稿先导出有滤镜版本，再删除滤镜轨道并以相同参数导出无滤镜版本。两份文件均为 854x480、30 fps、180 帧、6 秒、MOV/HEVC、`yuv420p`，并标记为 Rec.709。素材结构如下：

| 帧区间 | 内容 | 目的 |
| --- | --- | --- |
| 1-60 | 静态近景人像 | 检查皮肤区域、边缘和静态闪烁 |
| 61-180 | 多人舞蹈 | 检查动态 mask、帧序和时序稳定性 |

将无滤镜导出逐帧解码为 RGB PPM 后，探针在一个 CGL 3.2 core context、一个线程和一个 Effect handle 内完成 20 次预热，再以 `frameIndex / 30` 的单调时间戳连续处理 180 帧。输入和输出始终是两张独立纹理；后续输入帧通过 `glTexSubImage2D` 更新，未重建 context、SDK 或纹理。

为排除上一帧目标纹理残留，收紧后的探针会在每帧效果处理前将输出纹理恢复为已知测试颜色。重新处理 180 帧后，新旧两批输出逐帧字节一致，FFmpeg PSNR 为 `inf`；这说明该效果完整覆盖目标纹理，先前结果不依赖上一帧内容。

随后完全退出中文剪映主程序和托盘辅助进程，并确认系统中没有残留的剪映进程。独立探针仍在约 2.1 秒内完成一张真人帧的 20 帧预热、效果处理和 framebuffer 读回，退出码为 `0`；输出与连续序列中的对应帧逐字节一致。因此，当前本机互操作路径不依赖剪映 GUI 或后台进程正在运行，但仍依赖研究者自行提供的本机运行库、模型和效果包。

### ProRes 与无缩放控制实验

为继续隔离 HEVC 编码和空间缩放，后续完成了三层控制：

1. 将同一草稿改为 ProRes 422 HQ 对照；
2. 将同一草稿改为 ProRes 4444 对照；
3. 新建一次性草稿，输入、时间线和输出全部固定为 854x480，时间线缩放显示 `100%`。

前两层仍包含原始 640x360 素材到 854x480 时间线的缩放。第三层直接使用 854x480、30 fps、180 帧、6 秒的 ProRes 422 HQ 文件作为输入。无滤镜与“奥林巴斯”滤镜版均导出为 ProRes 4444、`yuva444p12le`、Rec.709；两份文件均由 `ffprobe` 验证为 180 帧和 6.000 秒。滤镜轨道覆盖完整 6 秒，强度为 `100`。

| 对照 | 全片 PSNR | 全片 SSIM | 静态人像 PSNR | 动态舞蹈 PSNR |
| --- | ---: | ---: | ---: | ---: |
| HEVC 4:2:0 | 37.291 dB | 0.946786 | 35.666 dB | 38.409 dB |
| ProRes 422 HQ | 39.140 dB | 0.959279 | 36.312 dB | 41.876 dB |
| ProRes 4444，剪映内有缩放 | 40.580 dB | 0.991692 | 37.093 dB | 44.796 dB |
| ProRes 4444，无缩放、原始输入 | 37.500 dB | 0.987756 | 35.500 dB | 39.002 dB |
| ProRes 4444，无缩放、剪映基线校准输入 | 40.741 dB | 0.991899 | 37.331 dB | 44.681 dB |

无缩放行需要区分两种输入语义：

- “原始输入”表示把和剪映完全相同的 ProRes 422 HQ 文件用 FFmpeg 解码为 RGB，再送入探针；这是最严格的文件级同源比较。
- “剪映基线校准输入”表示先取得同一草稿的无滤镜 ProRes 4444 导出，再把其 RGB 帧送入探针；这不是产品路径，只用于逼近剪映进入滤镜前的宿主色彩结果。

原始输入与剪映无滤镜导出之间只有 `41.569 dB / 0.995134`，说明即使尺寸完全相同，剪映的解码、色彩管理和 ProRes 导出往返也不是 RGB 恒等变换。直接同源探针因此同时承担了宿主路径误差和滤镜误差。

用逐像素残差比较 `(probe - input)` 与 `(ui_filtered - ui_baseline)` 后，全片 PSNR 从 `37.500 dB` 提高到 `39.619 dB`；静态段从 `35.500 dB` 提高到 `36.397 dB`，动态段从 `39.002 dB` 提高到 `43.086 dB`。残差分通道 PSNR 为红 `41.614 dB`、绿 `40.261 dB`、蓝 `37.841 dB`，蓝通道仍是最大误差来源。

将剪映基线帧直接作为诊断性探针输入后，全片达到 `40.741 dB / 0.991899`。与仍有空间缩放的 ProRes 4444 对照相比，全片仅提高约 `0.16 dB`，静态段提高约 `0.24 dB`，动态段变化约 `-0.12 dB`。因此，空间缩放并不是当前主要误差源；更值得继续追踪的是宿主 YUV/RGB 矩阵与量程、LUT 采样精度、skin mask 边缘和权重，以及算法配置。

### RGB/YUV 色彩路径校准

为把宿主色彩路径与人像算法分开，生成了一张 854x480 的 8-bit RGB PNG 色卡。色卡按 32x18 排列 576 个恒定色块，包含 8x8x8 RGB 立方体、16 级灰阶、16 个肤色样本和 32 个高饱和 HSV 色相。PNG 直接进入 854x480、缩放 `100%` 的剪映时间线，再无滤镜导出 ProRes 4444。`ffprobe` 显示导出为 `yuva444p12le`、TV range、BT.709。

将导出第一帧按不同矩阵和量程解码，并与原始 RGB PNG 比较：

| 解码路径 | 全图 PSNR | 色块中心 RMSE |
| --- | ---: | ---: |
| FFmpeg 默认 | 50.884 dB | 0.726 |
| BT.709 limited | 50.884 dB | 0.726 |
| BT.709 full | 27.481 dB | 10.770 |
| BT.601 limited | 28.564 dB | 9.512 |
| BT.2020 limited | 35.502 dB | 4.278 |

默认路径与显式 BT.709 limited 逐项一致，而且显著优于其他候选。由此可以把当前剪映 ProRes 对照固定为 BT.709 limited，不能再用 full range 或 BT.601 的猜测解释剩余误差。

在同一色卡上应用强度 `100` 的“奥林巴斯”，再用探针处理原始色卡，探针输出与剪映滤镜输出达到 `49.345 dB`。分通道 PSNR 为红 `49.008`、绿 `50.640`、蓝 `48.637 dB`，平均有符号误差为 `[-0.652, -0.402, -0.721]`，全通道 MAE 为 `0.633`。色卡没有触发可见的人像区域，因此这组结果主要测量两张 LUT、采样和全局色彩链路。蓝通道只比红通道低约 `0.37 dB`，不足以解释真人序列里约 3 至 5 dB 的蓝通道劣势。

### Skin mask 边缘与权重

使用仓库外的诊断性滤镜副本，分别输出探针的背景 LUT `L0`、皮肤 LUT `L1` 和原始 skin mask。对剪映最终输出 `U`，在每个像素上用最小二乘反推等效 mask：

```text
m_ui = clamp(dot(U - L0, L1 - L0) / dot(L1 - L0, L1 - L0), 0, 1)
```

只统计 `L0` 与 `L1` 差异足够大的像素，避免在两张 LUT 输出相同的区域除以接近零的数。首帧中，探针原始 mask 与剪映等效 mask 的相关系数为 `0.819`；探针 mask 均值为 `0.103`，剪映等效 mask 均值为 `0.220`。两者位置一致，但剪映在脸、颈肩和手臂上的有效权重更高，边缘也经过不同的收缩和羽化。

对 13 个采样帧搜索腐蚀、膨胀、Gaussian sigma、gamma 和仿射权重。静态首帧按 6 倍权重计入，以免 120 帧动态段完全压过 60 帧静态人像。最佳统一变换为：

```text
m_fit = clamp(1.182840 * Gaussian(erode5(mask), sigma=4)^0.65
              - 0.015195, 0, 1)
```

把该变换固定后重建全部 180 帧，结果如下：

| 区间 | 原始 mask PSNR | 拟合 mask PSNR | 原始 RGB 通道 PSNR | 拟合 RGB 通道 PSNR |
| --- | ---: | ---: | --- | --- |
| 全部 180 帧 | 40.731 dB | 41.814 dB | 43.421 / 41.258 / 38.755 | 43.495 / 42.379 / 40.222 |
| 静态人像 60 帧 | 37.406 dB | 38.749 dB | 40.806 / 37.951 / 35.202 | 40.890 / 39.338 / 36.942 |
| 动态舞蹈 120 帧 | 44.449 dB | 44.937 dB | 45.735 / 44.930 / 43.110 | 45.795 / 45.451 / 43.829 |

全片提高 `1.083 dB`，蓝通道提高 `1.467 dB`，相当于蓝通道均方误差减少约 29%。这把蓝通道问题定位为 mask 误差经皮肤 LUT 与背景 LUT 的蓝通道差异放大，而不是错误的全局蓝通道矩阵。

该变换不是可直接发布的修复。它改善了 `127/180` 帧，中位提升 `1.319 dB`，但 53 帧变差，最差倒退 `2.253 dB`，最好提升 `2.781 dB`。后续对原始 segmentation 纹理的直接检查表明，这个拟合是在补偿宿主算法状态差异，并不是效果包内还藏着一组固定的腐蚀、Gaussian 或 gamma 参数。

动态段再对原始 mask 做帧偏移验证：

| mask 相对剪映输出的帧偏移 | PSNR |
| ---: | ---: |
| -2 | 38.886 dB |
| -1 | 40.964 dB |
| 0 | 44.482 dB |
| +1 | 40.987 dB |
| +2 | 38.910 dB |

偏移 0 明显最佳，排除了简单的一帧算法延迟。不能把本次离线拟合参数硬编码到 QCut。

### Segmentation 工作分辨率与模型形状

“奥林巴斯”的 `algorithmConfig.json` 声明 `textureBlitter -> face -> skin_seg`，其中 blitter 的目标尺寸是 `128x224`。`skin_seg` 同时接收 blitter 和 face 的结果。模型文件名中的 `size100` 不是 `100x100` 输入尺寸。

从 `tt_skin_seg` 模型中提取的 CoreML 元数据显示输入名为 `data`，输出名为 `prob`，末层为 sigmoid。模型枚举了以下 NCHW 输入形状：

```text
[1, 3, 224, 128]
[1, 3, 128, 224]
[1, 3, 176, 128]
[1, 3, 128, 176]
```

默认编译图的 `data`、中间输出和 `prob` 都保持 `224x128` 空间分辨率。运行时再通过算法类型 `49` 取得 `Bach::SkinSegBuffer`，读取其 native 结果尺寸，得到：

| 画布 | ImageProducer | SkinSegBuffer |
| --- | ---: | ---: |
| 854x480 横屏 | 227x128 | 224x128 |
| 480x854 竖屏 | 128x227 | 128x224 |
| 640x480 4:3 | 224x168 | 176x128 |
| 480x480 方形 | 224x224 | 128x128 |

横屏、竖屏和 4:3 结果与模型枚举尺寸吻合，说明宿主先把短边约束到 128，再选择接近画面比例的模型形状。方形结果为 `128x128`，不在模型公开的枚举输入中，因此只能确认实际输出工作尺寸，不能据此断言方形网络 tensor 也直接使用 `128x128`；中间仍可能有裁剪或重映射。

后续 ByteNN 输入脉冲实验进一步区分了宿主路径：上述 `227x128` 是 Low-level 的第一级 bilinear 输出，随后还会缩到模型的 `224x128`；Swing 对同一 854x480 输入则先缩到 `398x224`，再缩到 `224x128`。两级尺寸的脉冲与二维纹理拟合结果见 [model-input-boundary.zh.md](model-input-boundary.zh.md)。

### 原始置信度与纹理格式

`SkinSegBuffer` 对应的同 context GL 纹理是单通道 `GL_R8`，放大与缩小采样均为 `GL_LINEAR`。它不是二值 mask：

| 输入 | 原始尺寸 | 8-bit 范围 | 均值 | 唯一值 | 0 占比 | 255 占比 | 软值占比 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 真人首帧 | 224x128 | 0-201 | 0.082577 | 201 | 8.2275% | 0% | 91.7725% |
| 无人物灰底 | 224x128 | 1-12 | 0.005211 | 8 | 0% | 0% | 100% |

这里的均值已归一化到 `[0, 1]`。“软值”只表示落在 0 和 255 之间。结合模型末层 sigmoid，可以把它理解为量化后的置信度式连续权重，但目前没有证据证明数值经过概率校准，也没有发现可供宿主设置的硬阈值。native 结构中紧随宽高的 float 会以 `reflector` 字段序列化；真人为 `1`、灰底为 `0`，但两个样本不足以确定其业务语义，因此不能把它当作置信度开关。

### Mask 后处理与内容状态

效果 shader 直接采样 `share://skinsegmask.texture` 的 alpha，并执行 `mix(LUT0, LUT1, mask.a)`。包中后续的 bilateral-like blur 处理的是已经完成 LUT 混合的 RGB 图像，不是 mask。

为验证低分辨率纹理到画布之间是否还有隐藏处理，用 OpenGL 半像素中心和 `GL_LINEAR` 采样矩阵反求原始 `224x128` R8 mask，再将其量化为 8-bit 并重新放大。四个采样帧与效果包灰度 mask 输出的结果为：

| 帧 | PSNR | 8-bit MAE | 最大误差 |
| ---: | ---: | ---: | ---: |
| 1 | 54.081 dB | 0.227 | 4 |
| 60 | 54.081 dB | 0.227 | 4 |
| 105 | 53.628 dB | 0.210 | 9 |
| 180 | 53.917 dB | 0.167 | 7 |

这组误差已经处于 R8 量化和数值反演量级，支持“原始 R8 mask 经过 `GL_LINEAR` 直接放大后进入 shader”。没有证据支持包内另有阈值、腐蚀、膨胀、Gaussian、gamma 或边缘羽化 pass。

连续内容仍会改变算法输出。用同一个 handle 连续输入 10 帧同一真人、20 帧同一灰底、再输入 10 帧同一真人：

| 区段 | 画布 mask 最大值 | 画布 mask 均值 | 区段内行为 |
| --- | ---: | ---: | --- |
| 初始真人 | 201 | 20.276 | 10 帧逐字节一致 |
| 灰底 | 8 | 1.236 | 从首帧立即切换，20 帧逐字节一致 |
| 返回真人 | 124 | 12.928 | 从首帧立即切换，10 帧逐字节一致 |

返回的是完全相同的真人像素，但 mask 没有恢复到初始值。这证明算法存在内容/历史相关状态；同时没有观察到逐帧衰减或回升，所以它不是一个简单的一帧延迟或固定 EMA 平滑。

对可能的模式开关做了四组 A/B：

| 开关 | 调用结果 | 输出比较 |
| --- | --- | --- |
| 包内 `skin_seg_is_video_mode=0/1` | 均加载成功 | 180 帧及切换序列逐字节一致 |
| 包内 `skin_seg_is_need_face=0/1` | 均加载成功 | 单帧及切换序列逐字节一致 |
| `bef_effect_set_algorithm_param(..., "skin_seg_is_video_mode", picture/video)` | 均返回 0 | 单帧及 40 帧切换序列逐字节一致 |
| `effectab_swing_force_detect_mode` bit 3 | 配置被接受 | 低层 Effect 路径逐字节一致 |

运行库字符串明确把 `effectab_swing_force_detect_mode` 的 bit 3 描述为“强制 skin segmentation picture mode”，并存在“set skin seg mode to picture/video”日志。静态调用链已经定位为：

```text
TESwingProcessUnit::setUpdateMode(int)
  -> TESwingEffectManagerV2::setUpdateMode(int, ITEMediaContext*)
  -> TESwingManagerInterfaceWrapper::setUpdateMode(int, ITEMediaContext*)
  -> AmazingEngine::SwingManager::setUpdateMode(int)
```

同时存在公开 C 入口 `bef_swing_manager_set_update_mode`。wrapper 与 C 入口都会把 mode 截为低 8 bit 后原样传给 `SwingManager`；`mode == 1` 会切换算法更新布尔状态，`mode == 3` 对应日志中的 `PREPARE_SEEK`。这证明当前低层 Effect handle 的 A/B 绕过了剪映真正的 Swing 宿主状态机，因此结果不变并不能证明 UI 的 picture/video mode 无效。尚未捕获的是剪映 UI 在具体预览、暂停、拖动和导出场景中实际传入的 mode 序列。

另一次 pipeline 实验因为算法结果未同步就绪，并在销毁 SDK 时退出 `139`，其低强度 mask 不具备可比性，已从有效证据中排除。

因此当前边界已经更精确：模型工作分辨率、原始软权重、R8 格式和包内线性采样已经定位；尚未定位的是剪映 UI 宿主进入算法前选择的 Swing update mode、预处理状态与状态重置时机，而不是效果包 shader 中的固定 mask 后处理。

### 人脸与皮肤链路边界

日志确认 `tt_face`、`tt_face_extra` 和 `tt_skin_seg` 模型均解析并加载成功，直接读回的动态 mask 也随人物移动，并覆盖脸、颈肩和四肢。对“奥林巴斯”滤镜实际需要的 skin mask 与双 LUT 混合链路，这已经是可见输出证据。

同时，通用 `FaceMakeupV2System` 在预热阶段仍报告 `facecount = 0`。当前探针没有通过独立算法结果 API 读回人脸框或关键点，因此不能把 skin mask 成功等同于人脸关键点链路已经证明。该缺口不阻塞此滤镜的双 LUT 重放结论，但会阻塞依赖关键点的美妆、五官变形和贴脸特效复刻。

### 结论与剩余误差

当前结果已从“能写入目标纹理”推进到“与中文剪映同素材、同帧、完整视频高相似重放”，并已经排除 HEVC 是唯一误差来源、空间缩放是主要误差源以及全局 RGB/YUV 矩阵错误。但它仍不是逐像素完美复刻，主要限制是：

1. 文件级同源视频输入仍会经过不同的宿主解码和 ProRes 往返，尽管 BT.709 limited 已由 RGB 色卡锁定；
2. skin mask 的模型形状、运行时工作尺寸、软权重和包内采样已直接读出，但剪映 UI 的 Swing update mode、预处理状态和状态重置时机尚未复现；
3. 真人素材的蓝通道残差仍最高，但无人物色卡证明它是 mask 混合放大，而不是全局蓝通道转换错误；
4. 人脸框和关键点尚未通过独立结果接口验证；
5. 诊断性基线校准不能替代产品路径中的确定性色彩管理。

下一轮应复用现有 `research/jianying-runtime-probe` Swing/Metal 宿主，通过 `bef_swing_segment_video_create_feature` 和 `bef_swing_segment_video_add_feature` 挂载滤镜，补齐模型 resource finder，并对 `bef_swing_manager_set_update_mode` 的 mode 序列做 A/B。若独立宿主仍不能复现，再对剪映 UI 调用点做运行时抓取。BT.709 limited、模型工作尺寸和包内 `GL_LINEAR` 路径已固定，不再需要继续盲枚举全局矩阵或给 mask 叠加经验模糊。

## 产品边界

本次成功证明的是本机互操作性和 GL 设备要求，不代表第三方二进制可以进入 QCut 产品。QCut 产品路径仍应是：

- 纯 LUT：QCut 自有严格解析器、3D texture 和混合 shader；
- 人像滤镜：获得授权或 QCut 自有的人脸/皮肤分割模型；
- 回归测试：使用 QCut 自有测试素材和可提交的比较指标；
- 第三方缓存：仅作为仓库外的行为参考，不提交、不上传、不分发。
