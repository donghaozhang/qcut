# V2 探针 skin mask 绑定修复

记录时间：2026-08-11

## 单一问题

本轮只验证一个问题：Swing V2 路径渲染滤镜时，交付到 `SkinSegInfo` 的 CPU mask 是好的还是坏的。

判据在实验前固定：mask 是好的则断点在 shader 绑定；mask 是空或坏的则断点在算法结果发布，需要继续往上游追。

## 方法

沿用 [model-input-boundary.zh.md](model-input-boundary.zh.md) 已经静态确认的对象布局，在 `Bach::SkinSegInfo::textureId`
入口安装临时进程内观察器，读取 `SkinSegInfo + 0x18` 的 `PrimitiveVector<unsigned char>`：

```text
SkinSegInfo + 0x0c  int32  width
SkinSegInfo + 0x10  int32  height
SkinSegInfo + 0x14  float  reflector
SkinSegInfo + 0x18  PrimitiveVector<unsigned char>   -> impl + 0x10 begin / impl + 0x18 end
```

该消费点 `libcccreator + 0x99bb60` 在低层 Effect 路径和 Swing V2 路径是同一个函数，所以一个观察器可以同时覆盖两条路径。
观察器只写文件，并要求 `end - begin == width * height` 才落盘。

对照实验强制两条路径加载同一个旧 skin_seg 模型（`tt_skin_seg_v5.0.model`，MD5 `2b5a3aed4a9a45a67b7febabe9247d6e`），
输入为同一批 854x480 帧。

## 结果：mask 交付正常，渲染只用上 7%

| 指标 | Swing V2 | 低层 Effect | 比值 |
| --- | ---: | ---: | ---: |
| 交付的 CPU mask 均值 | 0.0844 | 0.0765 | 1.10 |
| 渲染输出反推的等效 mask | 0.0160 | 0.2408 | 0.07 |

V2 交付的 mask 不但不是空的，强度还略高于低层路径。低层路径在同一素材上 20 次读取逐字节一致（无状态），
V2 逐 pass 变化（recurrent 状态在更新），两者都符合预期。

因此判据的第一个分支成立：**断点在 shader 绑定，不在算法结果发布。**

## 根因：native buffer 的第三个标志

两条路径交付的 mask 内容几乎相同，只差一个垂直翻转：

| 比较方式 | 相关系数 |
| --- | ---: |
| 原样 | -0.1164 |
| V2 mask 垂直翻转后 | **+0.9777** |

`AmazingEngine::RendererDevice::createTextureFromNativeBuffer` 的第三个 bool 参数决定效果采样 native buffer 时使用的
垂直约定。该标志为假时，交付的 mask 被上下颠倒地绑定，皮肤 LUT 落在镜像位置，真实皮肤区域的等效 mask 因此塌到接近零。

同一标志还改变读回的通道序。置位后纹理已按 RGBA 顺序读回，此时再次执行 `convertBgraToRgba` 会把 R 与 B 交换。

单变量验证（854x480，同模型，同输入，第 70 帧）：

| 配置 | 等效 mask | 与剪映 mask 的空间相关 | 人像内部 PSNR | 全图 PSNR |
| --- | ---: | ---: | ---: | ---: |
| 第三标志为假（原默认） | 0.0160 | 0.141 | 21.113 | 30.442 |
| 第三标志为真，仍做通道转换 | 0.3713 | 0.891 | 15.907 | 23.756 |
| **第三标志为真，跳过通道转换** | **0.2808** | **0.950** | **37.699** | **44.521** |
| 低层 Effect 参照 | 0.2408 | 0.937 | 33.828 | 42.895 |
| 剪映目标 | 0.2996 | — | — | — |

同时排除了两个方向：翻转输入帧无效（管线对输入方向自洽，mask 与渲染一起翻转，相对错位不变）；
关闭 native 输入纹理更差（算法在该模式下只执行了 2 次，整图 PSNR 降到 22.8）。

## 修复

两处改动，均在 `research/jianying-runtime-probe/`：

1. `probe.mm`：`optionalNativeTextureFlags` 未设置环境变量时返回 `{false, false, true}`，而不是全假。
2. `filter-probe.mm`：`nativeTextureFlags[2]` 为真时跳过 `convertBgraToRgba`。

修复后的探针输出与手工修正的结果逐字节一致。

## 本轮作废的旧结论

- 此前所有 Swing V2 的 parity 数字（全片 31.720、静态 31.412、人像内部 22.552、内部蓝通道 18.436）
  都是在第三标志为假的条件下测得的，mask 实际没有进入混合，全部作废。
- “V2 宿主会压低同一模型的 mask”不成立。同模型下 V2 修复后优于低层路径。
- “剩余差距 100% 来自分割 mask 权重”需要收窄：修复前的差距中有相当部分来自纹理绑定，而不是模型输出。

## 模型选择

`tt_skin_seg_video_seg_fp16_v1.0`（MD5 `cd5474732a4b56b7fffceba8a83d7c1e`，407541 字节）随剪映安装包提供，
无需触发下载即可用于本机对照。它在修复后的 V2 中 IoU 最高（全片 0.749），但人像内部 PSNR 低于静态模型
（35.596 对 38.627）。两个模型互有胜负，不存在“换成剪映所用模型即可对齐”的结论。

在低层 Effect 路径中强行使用该 video 模型会退化（静态段等效 mask 0.0039，IoU 0.000），
与 recurrent 张量在该宿主下未被驱动一致，因此它不能脱离 V2 宿主使用。

## 在修复后的基线上重跑受影响的实验

此前的排除结论都是在绑定错误的 V2 上得出的，因此逐项重跑。结果是全部维持原判：

| 实验 | 损坏基线 | 修复后基线 |
| --- | --- | --- |
| update-mode 三种预热解释（`3;1;2` / `0,1,1,2` / `0;1;1;2`） | 无改善 | 三者输出完全相同（人像内部 45.027） |
| `EnableImageQuality` 0/1 | 逐字节相同 | 逐字节相同 |
| `EnableAdjustColorWithFloat` 0/1 | 逐字节相同 | 逐字节相同 |
| `AlgorithmCacheFlag` 0/9 | 逐字节相同 | 逐字节相同 |
| manager init mode 0/2 | 逐字节相同 | 逐字节相同 |
| texture data code 0/1 | 未测 | 逐字节相同 |
| mask 后处理 holdout 标定 | 恢复 9.8% | 恢复 2.9%，改善 38 / 退化 34，最差 -1.83 dB |

因此之前唯一错误的是 V2 自身的数字，这些排除判断不需要推翻。

后处理标定的否定结论在修复后反而更强，但原因不同：此前是探针 mask 与目标的重叠太低（IoU 0.24），
现在 IoU 已达 0.735、相关 0.939，固定变换没有可利用的系统性偏差。

## 残余差距的性质

对动态段做分解：

- 无时序滞后。按帧偏移比较时，偏移 0 在全部采样帧上都优于 ±1。
- 逐帧 mask 与剪映等效 mask 的相关为 `0.925` 到 `0.958`。
- 用最优全局增益拟合后误差只下降 `1.3%`，即 `98.7%` 的 mask 误差是逐像素形状差异，不是幅度差异。

误差的空间分布（占总平方误差比例）：

| 区域 | 误差占比 | 面积占比 | RMSE |
| --- | ---: | ---: | ---: |
| 核心皮肤 `m_UI > 0.8` | 15.9% | 9.2% | 0.1274 |
| 软边缘带 `0.2 - 0.8` | 30.6% | 7.5% | 0.1959 |
| 外部 `< 0.2` | 53.5% | 83.3% | 0.0777 |

软边缘带以 `7.5%` 的面积贡献 `30.6%` 的误差，单位误差是核心区的约 1.5 倍。分歧集中在边界过渡，
而不是「哪里是皮肤」这一判断本身。

## 人脸链路更正

此前记录称探针的人脸结果不可用（`FaceMakeupV2System` 报告 `facecount = 0`）。该结论来自日志与
静态推断，现已由运行时观测推翻。

`_FsNew_DoPredict` 在 `libcccreator` 中是未定义符号，由 `liblens.dylib` 导出，因此可以用
`DYLD_INSERT_LIBRARIES` 的 `__DATA,__interpose` 直接拦截并记录真实参数与结果。观测到：

```text
FsNew_CreateHandlerFromBuf rc=0 config=0x22007f  model=888558 bytes (tt_face)
FsNew_AddExtraModelFromBuf rc=0 type=0x900       model=691859 bytes (tt_face_extra)
FsNew_DoPredict            rc=0 fmt=0 227x128 stride=908 orientation=0 config=0x20001
```

预热帧之后的结果缓冲区含有有效人脸数据：矩形 `[87 49 141 104]`、成对的关键点浮点坐标、
置信度 `1.00`，矩形逐帧微动说明跟踪在工作，人脸数量字段位于 `+0x6b28` 且稳定为 `1`。

因此以下说法作废：探针人脸检测失败；`stride` 可能为 `0`；输入朝向导致检测失败；`227x128` 下人脸过小。
其中 `stride` 实测为 `908`（即 `227 * 4`），参数完全合法。此前记录的
`AlgorithmSkinSeg face count is zero!!!` 只在 `need-face1` 诊断包下出现，真实滤镜包一次都没有。

## 人脸对 mask 无影响

在人脸结果已确认可用的前提下重新验证 `skin_seg_is_need_face`，三层证据一致：

1. 真实滤镜包注入 `0` 与 `1`，180 帧输出逐字节相同；
2. 运行日志中该参数没有任何读取记录；
3. 直接从 `algorithmConfig.json` 删除 `face_0 -> skin_seg_0` 这条边，180 帧输出仍逐字节相同。

第三项是决定性的：删除连线后等效 mask 仍为 `0.1717`，mask 存在且非平凡，因此「相同」不是空运行造成的。

结论：`skin_seg` 的 mask 完全由 blitter 图像计算，人脸输入虽然在图中声明，但不参与该模型的计算。
`skin_seg_is_need_face` 无效的原因不是开关未生效，而是下游不消费这一路输入。人脸引导因此不是
残余差距的来源。

## 方法论记录

本轮两次得出过反向结论，原因相同：直接采用静态反汇编推断的结构偏移而未先验证。人脸数量字段被推断为
`+0x6AD0`，该处恒为 `0`，据此得出「人脸检测失败」；实际字段在 `+0x6b28`。

因此后续研究应遵循：反汇编用于定位可观测边界，具体偏移与语义必须由运行时观测确认后才能作为结论依据。

## 直接取得剪映自身的 mask

在此之前，比较目标一直是从剪映输出反推的等效 mask。反推只在两张 LUT 差异足够大的像素上成立，
且无法证明它等于剪映的真实分割输出。

剪映的渲染进程（`--lvve-service`，Frameworks 内的嵌套 app）带 hardened runtime 且缺
`disable-library-validation` 与 `allow-dyld-environment-variables`，实测注入被剥离：主进程可以
装载观察库，渲染服务进程不能，因此读不到它的内部结果。主 app 虽有这两项授权，但 skin_seg 不在
主进程执行。

改用不依赖注入的办法：滤镜包是数据，其片元着色器最后一行决定输出内容。把剪映自己缓存中那份包的
着色器输出改成 mask，再用剪映正常渲染，剪映就会把它自己的 mask 画出来。

```glsl
// 原始
out.gl_FragColor = res;                                  // mix(LUT0, LUT1, mask)
// 诊断
out.gl_FragColor = float4(mask.w, mask.w, mask.w, 1.0);  // 直接输出 mask
```

macOS 上剪映走 Metal，因此必须改 `shaders/filter-0-0a92/metal/5a97.frag`；仓库外既有的诊断包
只改了 `gles2` 变体，对剪映无效，这也是此前一直没走通的原因。

操作纪律：改前完整备份滤镜包，取完数据后整目录还原并用 sha256 校验与原始逐字节一致。本次已还原。
导出得到 854x480、180 帧的 mask 视频，保留在仓库之外。

### 反推方法得到验证

以真实 mask 为基准检验此前一直使用的反推 mask：

| 对照 | 结果 |
| --- | ---: |
| 相关系数 | `0.9962` |
| MAE | `0.0244` |

因此本文此前所有基于反推 mask 的结论（天花板 `51.3 dB`、各项 holdout 评估）均成立，不需要推翻。

## 以真实 mask 重新排序

此前依据人像内部 PSNR 选出的最佳组合是逐像素取较大值。以真实 mask 为基准后，该排序被推翻。
下表为 180 帧结果，`band` 为过渡带面积占比：

| 候选 | 对真实 mask 的 MAE | 相关 | IoU | band | 人像内部 PSNR | 全图 PSNR |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 剪映真实 mask | — | — | — | **0.1062** | — | — |
| 逐像素较小值 | **0.0332** | 0.936 | 0.736 | 0.1041 | 34.815 | 43.181 |
| **逐像素平均** | 0.0334 | **0.953** | **0.785** | 0.1351 | 38.039 | **44.726** |
| video_seg | 0.0350 | 0.932 | 0.757 | 0.1132 | 35.580 | 43.169 |
| ByteNN | 0.0385 | 0.940 | 0.739 | 0.1338 | 38.705 | 43.936 |
| 逐像素较大值 | 0.0403 | 0.943 | 0.757 | 0.1429 | **40.891** | 43.921 |

两套排序几乎相反：按人像内部 PSNR，取较大值第一；按与真实 mask 的距离，取较大值最后。

原因是取较大值系统性放大 mask（`band` 0.1429，为全部候选中最宽，真实值为 0.1062）。人像内部
PSNR 只在 `mask >= 0.5` 区域计分，放大 mask 恰好在该区域少犯错，代价落在指标不覆盖的地方。

**结论：采用逐像素平均，不采用逐像素较大值。** 平均在与真实 mask 的相关、IoU 和全图 PSNR 上同时
最优，且没有通过放大 mask 换取分数。逐像素较小值虽然 MAE 与 band 最接近真实值，但人像内部只有
`34.815 dB`，漏掉了真实皮肤区域。

## 评价指标纪律

本轮出现过一次严重的指标失效。对 mask 施加 S 型对比度曲线后，人像内部 PSNR 从 `38.631` 升到
`42.520`，训练与保留集划分也显示良好泛化；但同一配置的全图 PSNR 从 `43.936` 跌到 `35.746`。
拟合出的 pivot 为 `0.25`，而 `sigmoid(3 * (0 - 0.25)) ≈ 0.32`，意味着纯背景也被抬到 32% 的皮肤
LUT，`100%` 的背景像素被误加。人像内部指标完全看不到这一点。

改用全图误差作为拟合目标后重新搜索，同一变换族的最优解退化为恒等变换（`erode=0, blur=0,
gamma=1.0`），S 型曲线的最优参数也不再改善任何指标。此前记录的「mask 后处理可恢复 2.9%」同样是
只看人像内部得到的，一并作废。

训练与保留集划分不能防止这类错误，因为两者使用同一个有偏目标。因此规定：任何 mask 后处理必须同时
报告人像内部与全图两项指标，任一项退化即判为失败；涉及与剪映相似度的结论还须同时报告对真实 mask
的 MAE 与 IoU，因为代理指标与真值指标在本问题上会给出相反排序。

## 剩余差距

以逐像素平均计，全图 `44.726 dB`，人像内部 `38.039 dB`，天花板 `51.34 dB`。

已排除：人脸引导、全局增益、时序滞后、update-mode、全部已测 AB 开关、提高 blitter 工作分辨率、
图像引导上采样，以及任何固定 mask 后处理。

残余的主要特征是边界锐度：真实 mask 的过渡带为 `0.1062`，我们最好的候选为 `0.1351`，且真实值窄于
`224x128` mask 经双线性放大所能达到的下限（实测 `0.1236`）。我们的渲染链已验证忠实——渲染出的
mask 与自身 CPU mask 的理想双线性放大相关 `0.9979`——因此差异位于剪映如何把低分辨率 mask 交付到
画布，而不是我们的实现。
