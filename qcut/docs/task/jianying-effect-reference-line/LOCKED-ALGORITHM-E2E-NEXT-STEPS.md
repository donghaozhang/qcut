## 目标

当前特效目录中有 41 个精确包版本因为包含 `matting`、`face`、
`skeleton`、`depth` 等算法节点而保持锁定。这里的“锁定”表示：

1. 当前 `effectId + packageHash` 尚未通过模型开/关隔离验证；
2. 不能证明模型输出真实参与了最终画面；
3. 不能因为包能启动、画面有变化或模型文件存在就直接加入白名单。

本任务的目标是逐包建立可重复证据：同一输入、同一参数分别执行模型开启和
模型关闭渲染，只有模型开启结果稳定、完整，并且与模型关闭结果存在可解释差异
时，才允许把该精确包版本加入
`electron/jianying-effect/verified-algorithm-packages.ts`。

## 已发现的验证基础设施问题

### 1. 模型根目录优先级可能被全局排序破坏

TypeScript 侧声明的顺序是 QCut 私有缓存优先，其次才是剪映缓存和应用包。
但 `ModelCatalog` 收集所有根目录的文件后，对完整绝对路径执行一次全局排序。
这样 `/Applications/...` 会排在 `/Users/...` 前面，stem 匹配可能选择应用包中的
旧模型，而不是 QCut 私有缓存中的优先版本。

本轮 `可爱涂鸦` 崩溃前实际解析到：

```text
/Applications/VideoFusion-macOS.app/Contents/Resources/models/
mattingmodel/tt_matting_v15.0.model
```

下一步应保留“根目录优先级”，只在单个根目录内部排序；精确文件名和 stem
匹配都必须按根目录顺序进行。修复后先重跑 `可爱涂鸦`，确认崩溃是否消失。

### 2. Matting 测试素材仍不足以解释 `SSIM = 1`

本轮人物素材确实有人像，但 `ref-clip-body-1280x720.mp4` 与人脸素材在 1 秒
抽帧后像素完全一致，并不是真正独立的全身动作素材。它适合初步抠像验证，
但不适合证明骨骼检测，也不能覆盖所有依赖轮廓运动的 matting 包。

在继续之前应准备四种本地专用测试片：

1. `face`：单人、正脸、无遮挡、头肩完整、持续轻微转头和表情变化；
2. `matting`：单人全身、前景与背景对比明显、手脚和头发持续运动；
3. `skeleton`：全身始终在画面内，手臂和腿有明显关节动作；
4. `depth`：近景人物或物体、中景主体、远景背景同时存在并有相机位移。

每段固定为 6 秒、1280x720、30fps，并生成经过相同色彩转换的无特效基线。

### 3. 失败记录丢失了部分诊断信息

批处理脚本先计算“特效输出 vs 基线”的 SSIM，再执行模型隔离检查；但隔离检查
抛错后，失败记录没有保存前面已计算的基线 SSIM。于是 `模型开 = 模型关` 时，
无法区分以下两种情况：

- 两边都等于原片，算法和特效都没有工作；
- 两边都有相同特效，说明该包实际上不依赖模型，分类可能过度保守。

下一步应让失败记录也保存：

- `baselineSsim`：模型开启输出与基线；
- `controlSsim`：模型开启与模型关闭；
- 每帧最大差异及发生时间；
- 模型开启、关闭各自的输出帧数和退出状态；
- 所有模型请求及最终解析路径；
- 崩溃时完整桥接日志路径，而不是仅保留尾部 500 字符。

### 4. 缺少模型需要显式别名或真实补包，不能模糊匹配

本轮缺少 `tt_matting_relighting`，而缓存中存在名称接近的
`tt_matting_relight`。二者不能仅凭前缀相似就绑定。应从算法包的模型请求、
剪映对应版本和模型元数据证明兼容后，才能增加显式别名。

历史失败还出现过以下缺失项，后续每个都按同样规则处理：

```text

tt_baoman_tk
tt_avatar3dsticker
tt_lm_3d
tt_lm_3d_mean_face
```

## 下一步执行顺序

### 阶段 A：先修验证工具，不动白名单

1. 修复模型目录优先级，增加“优先 QCut 私有模型”的单元测试。
2. 让 `manifest.jsonl` 的完成键使用 `effectId + md5`，避免新包版本被旧成功
   记录跳过。
3. 失败时保存 baseline/control 两组 SSIM、逐帧差异、完整日志和模型解析表。
4. 给每次运行建立独立 run id，避免追加式清单把不同桥版本的结果混在一起。
5. 为模型开启和关闭输出保留短期本地文件，自动生成时间扫帧联系表；人工确认后
   再删除。

### 阶段 B：替换测试素材

1. 生成真正的 matting、face、skeleton 和 depth 专用输入及基线。
2. 用一个已经在 365 白名单内、且属于对应能力的已知成功包做正对照。
3. 正对照必须满足模型开启/关闭差异阈值，否则该批素材或桥接环境无效，整批结果
   不得用于解锁。

### 阶段 C：按风险由低到高重跑

1. 先重跑剩余 3 个纯 matting 包。
2. 再重跑 7 个 `SSIM = 1` 的 matting 包，检查 baseline SSIM 后重新分类。
3. 单独复现并修复 `可爱涂鸦` 崩溃，再运行 matting + script 包。
4. 运行纯 face/faceDetect，再运行带 expression、freid、idream、3D fitting 的包。
5. 正确全身素材和正对照通过后运行 skeleton。
6. 使用层次明显的素材运行唯一 depth 包。
7. 最后研究 3 个 script/ext_texture_producer 包是否应退出 CV 算法模式。

### 阶段 D：只放行有完整证据的精确包

每个候选必须同时满足：

1. 包的 md5 与目录元数据一致；
2. 模型开启渲染退出码为 0，输出 180/180 帧；
3. 模型关闭渲染也完整结束；
4. `controlSsim` 显示模型输出有稳定、非噪声贡献；
5. 时间扫帧确认差异落在预期主体、脸、骨骼或景深区域；
6. 没有错误模型绑定、镜像 Mask、闪帧、全黑、透明度错误或崩溃；
7. 只把本次验证的 `effectId:packageHash` 加入白名单；
8. 运行算法支持单测、目录统计和至少一个 CLI 视频 E2E。

禁止仅凭以下条件放行：模型文件存在、进程启动成功、输出视频存在、画面相对原片
有变化、同名旧版本曾经成功，或者剪映 UI 中看起来可用。
