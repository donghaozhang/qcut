# 剪映封面与 QCut：UI 实测和补齐记录

日期：2026-09-06。工作分支：`codex/cover-design`。现有 PR：[#463](https://github.com/Quriosity-agent/qcut/pull/463)。

## 结论

剪映的封面是独立编辑工作区，不只是“选一张图片”。本轮把 QCut 原来的来源选择小弹窗扩展成模板、文字、画布、取帧和保存组成的可编辑流程。下列结论来自本机原生剪映和 QCut 浏览器 UI 的实际操作，不以用户截图代替实测。

QCut 使用五款原创文字模板；没有复制剪映的模板图片、字体或私有资源包。当前完成的是基础交互与持久化链路，不是剪映素材库、模板格式或视觉效果的完整兼容。

## 原生剪映观察

应用：`/Applications/VideoFusion-macOS.app`，本机剪映专业版。此次没有另行确认版本号。

1. 从时间线“封面”入口打开独立窗口；左侧模板/文本，中央画布，顶部文字工具，底部撤销、重做、裁剪、导入与胶片条，右下角取消/设为封面。
2. 模板按默认、推荐、生活、游戏、知识、时尚、影视、美食等分类，主要使用双列图片卡片。部分卡片需要下载。
3. 新建文字后出现选框和旋转控件；顶部可以编辑内容、字体、颜色、阴影、描边、背景、气泡、排列/对齐、粗斜体和下划线。
4. 描边有独立弹出面板，包含颜色、十六进制颜色值和宽度，并非只有开关。
5. 裁剪进入单独模式，显示网格，暂时隐藏文字并禁用模板/文字编辑，完成后返回。
6. 应用旅行模板后产生多个可编辑文字元素；此前手动添加的文字保留。多选状态不能直接编辑单个文字的内容，需要先单选。
7. 最终点击取消，返回原项目，未设为封面、未导出、未修改其正式封面。

观察 6 是本轮重要行为依据：模板应拥有自己的图层，而不是每次切换都清空用户手动文字。

## 对照与实现

| 交互 | QCut 之前 | 本轮 QCut |
| --- | --- | --- |
| 入口 | 预览工具栏；主轨道标记仅装饰 | 两处均打开同一个编辑器 |
| 工作区 | 图片/当前帧选择与缩放适配 | 左侧素材区、顶部文字工具、中央画布、底部来源/保存 |
| 模板 | 无 | 五款原创模板和原图；分类、双列实际背景预览 |
| 模板编辑 | 无 | 模板生成文字图层；切换保留手动文字；单层可编辑 |
| 文字 | 无 | 内容、字号、系统字体族、颜色、B/I/U、对齐、层级、删除 |
| 样式 | 无 | 描边、阴影、背景开关；参数固定，非剪映完整样式面板 |
| 几何 | 背景 contain/cover | 文字拖动、键盘位置调整、框宽高、旋转；背景缩放/位置/裁剪模式 |
| 来源 | 导入图片/当前播放头帧 | 增加帧号、前后帧、滑杆和七点按需胶片缩略图 |
| 历史 | 无独立设计历史 | 最多 60 步撤销/重做，拖动完成记一步，取消拖动不记录 |
| 重开 | 单张背景 | 背景来源、裁剪、模板与文字属性一起恢复 |
| 布局 | 紧凑弹窗 | 桌面双栏；窄屏模板置顶、工具换行、画布保持项目比例 |

文字缩放和旋转当前使用工具栏控件，选框只支持移动，没有假装可操作的缩放角点。字体仅使用 sans-serif/serif/monospace 三类系统字体，跨系统字形仍可能不同。

## 实现结构

- `packages/editor-core/src/cover/`：模型、验证、模板、独立历史。一个背景和最多 20 个文字图层，兼容旧版单背景设计。
- `apps/web/src/components/editor/cover/`：工作区、模板/文本库、文字工具、画布手势、来源条和异步状态。
- `apps/web/src/lib/cover/`：复用现有时间线文字渲染器；统一模板缩略图、交互预览和正式输出的绘制逻辑。
- `apps/web/src/lib/export/export-still-frame.ts`：增加可选指定时间，按项目 FPS 对齐，不移动播放头。
- `apps/web/src/components/ui/dialog.tsx`：增加可选固定布局；原有弹窗默认滚动结构不变。

保存仅允许发布当前设计对应的已完成渲染结果。来源请求有同步忙碌锁、卸载及请求代次检查；重开设计不进入撤销栈。取消不更新正式项目封面；复制资源时保留文字层，不把文字当成图片资源读取。

## 验证记录

源码在 `$SSD_ROOT/qcut/qcut`，依赖与运行镜像在 `$HOME/.cache/qcut-cover-validation/qcut`。这是 exFAT SSD 与 APFS 依赖环境的分离，不是两个开发分支。

1. 通过真实文件选择器导入自生成 H.264 校准视频，1280×720、24 FPS、4 秒，再通过 UI 加入时间线；QCut 项目为 1920×1080、30 FPS。
2. 打开封面自动取得第 0 帧；应用旅行模板，将标题改成“夏天的旅行”。展开七点缩略图，指定第 36 帧，即 1.2 秒。
3. 新建“手动文字保留”，开启下划线与背景，将纵向位置调整到 0.7。另一次编辑中实测模板切换保留手动文字，撤销恢复此前模板及编辑内容。
4. 点击设为封面，等待弹窗关闭后刷新页面；重新打开确认来源帧、模板标题、手动文字、位置和样式均恢复。一次过早刷新中断保存的尝试不计为成功证据。
5. 从主轨道入口打开，设置背景缩放 1.01、横向位置 0.51，保存并等待关闭，再刷新重开，确认参数恢复。
6. 1440×900 桌面与 390×844 窄屏目视检查；窄屏画布为约 344×193.5，没有整页横向溢出或工具遮挡。截图在会话中查看，未写入历史截图目录。
7. 保存后加载的预览图片为 1920×1080；在裁剪参数最终调整之前，对该图片做 64×36 离屏采样，得到 424 种 RGBA 颜色，FNV-1a 32 位采样指纹为 `1539991225`。它只证明当前测试图片非空白，不是导出文件 SHA-256 或剪映对齐指标。

自动化验证：97 项测试、14 个测试文件通过，包含模型/模板边界、长中文文本适配、裁剪几何、资源复制、指定帧、不发布旧渲染、并发点击、卸载、StrictMode、指针取消、共享弹窗与主轨道入口。Web TypeScript 与变更文件 Biome 检查通过。

测试环境的时间线导入曾输出 jsdom 未实现 Canvas `getContext()` 的警告，但相关测试没有失败；实际画布渲染另外经过上面的浏览器像素和目视检查。

运行命令见 [README](./README.md)。开发入口：`http://127.0.0.1:5188/`。

## 仍有差异

- 尚无气泡、自定义字体下载、花字包、完整描边/阴影/背景参数、多选和直接缩放/旋转手柄。
- QCut 模板是内置文字预设，不是剪映模板包解释器；未实现素材包导入、参数绑定或云端模板目录。
- 背景裁剪保持项目画布比例，没有任意裁剪比例预设或完整旋转裁剪工具。
- 胶片条是七点抽样，不是剪映完整连续缩略图缓存；复杂时间线生成可能较慢。
- 本轮渲染和保存是浏览器 Web 路径；未验证原生 Electron、复杂转场逐像素一致性、跨机器迁移或原生项目包导出。
- 存储仍是按项目隔离的 OPFS；清除站点数据会删除封面。取消或换图的未引用资源保留至项目删除，尚无即时垃圾回收。
- 项目复制/删除的资源行为有单元测试，但本轮未做这两项完整 UI 生命周期复测。

私有参考缓存仍为 78 个图片载荷、零完整可编辑模板包；本轮没有新增或发布剪映素材。历史缓存信息见 [README](./README.md)。
