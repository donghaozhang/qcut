# 剪映“画面 > 基础”能力实现研究

> 研究对象：剪映专业版 macOS 11.3.0
>
> 记录日期：2026-08-30
>
> 范围：用户截图中“画面 > 基础”面板的全部能力
>
> 性质：只读互操作研究，不复制或分发剪映私有模型、着色器、素材与缓存

## 结论先行

这些开关并不属于同一种实现。剪映至少使用了四条不同的处理链：

1. **实时合成**：位置、缩放、旋转、透明度、混合模式、变形、背景填充。
2. **本地离线预计算**：防抖、去频闪、运动模糊，以及部分降噪和补帧模式。处理完成后写入缓存或派生视频，再交给预览与导出使用。
3. **分析后生成元数据**：智能运镜、镜头追踪、智能裁剪。算法主要生成轨迹、裁剪窗口或关键帧，不直接生成每一帧画面。
4. **云端生成**：超清画质、AI 消除、AI 扩展、AI 对口型等。剪映明确提示上传素材，任务完成后把生成结果路径写回草稿。

“一键画质提升”不是第五种底层算法，而是一个**能力编排器**：先分析素材，再选择画质增强、色彩增强、智能打光、补帧或补分辨率等独立模块。

## 真人视频对打状态

本目录现在包含十项 QCut 与剪映的同源真人视频 E2E。七项像素功能使用带抖动、闪烁和噪声的 3 秒真人轨；三项智能功能使用同一真人的小主体构图轨。双方都保留实际导出、UI 截图、媒体探针和四宫格同步对比。

- QCut 十项均产生不同于基线的实际视频。
- 剪映十项均经过真实 UI 与独立时间线导出。
- QCut 补帧尾帧缺失已在本轮修复；非方形像素源的输出几何仍与剪映不同。
- QCut 的防抖、降噪、补帧和超分是本地替代实现，不能按剪映模型名宣称等价。
- 2026-08-31 新增第一条剪映本机私有 Provider：防闪烁已从“模型可加载”提升到连续帧输入、派生视频缓存、CLI/UI 时间线替换和真人 E2E；私有文件仍不分发。

完整结论见 [本机缓存防闪烁实现](./PRIVATE_RUNTIME_DEFLICKER.zh-CN.md)、[English private-runtime deflicker](./PRIVATE_RUNTIME_DEFLICKER.en.md)、[中文真人对比报告](./REAL_PERSON_COMPARISON.zh-CN.md) 和 [English real-person comparison](./REAL_PERSON_COMPARISON.en.md)。

## 草稿和运行时分层

剪映草稿把相关状态拆成三层：

| 层 | 主要内容 | 代表字段 |
| --- | --- | --- |
| 片段层 | 可实时修改、可打关键帧的属性 | `clip.alpha`、`clip.rotation`、`clip.scale`、`clip.transform`、`uniform_scale`、`common_keyframes` |
| 素材层 | 裁剪、角点、稳定、智能运镜等视频状态 | `crop`、`corner_pin`、`stable`、`smart_motion`、`surface_trackings` |
| 算法层 | 重型视频处理和生成任务 | `video_algorithm.deflicker`、`noise_reduction`、`quality_enhance`、`super_resolution`、`mouth_shape_driver` 等 |

运行中的剪映还会启动独立的 `--lvve-service`。本地重型任务通过专门 Client 提供开始、暂停、恢复、取消和结果路径查询接口，因此不会把全部计算塞进 UI 线程。

## 最重要的产品判断

### 1. 重型效果不是预览时从头计算

防抖、去频闪、运动模糊、降噪、补帧、超分等都有独立任务对象和结果路径。合理的实现是：

`源素材 -> 算法任务 -> 缓存/派生素材 -> 预览与导出复用`

QCut 不应在每次播放或拖动参数时重新处理整段视频。

### 2. “运镜”和“画质生成”要分开建模

智能运镜、镜头追踪和智能裁剪的核心产物是时间序列元数据；超清、AI 消除、AI 扩展和对口型的核心产物则是新媒体。二者如果共用一个模糊的 `effect` 类型，会导致撤销、缓存、导出和进度管理全部变复杂。

### 3. 本地/云端是每个能力的属性，不是全局模式

降噪和补帧在同一个 UI 内就同时提供本地与云端模型。QCut 应让 Provider 决定执行位置，并统一暴露任务状态、进度、取消、缓存命中和结果校验。

### 4. 背景填充不等于 AI 扩展

背景填充只是画布合成，源画面之外显示纯色、图片或模糊副本；AI 扩展会生成原素材中不存在的像素，需要云端任务和新的结果素材。这两个功能不应共享同一个实现开关。

## QCut 建议的实现顺序

1. 先统一片段变换、角点、混合和画布背景的数据模型与关键帧。
2. 再建立通用 `VideoAlgorithmJob`、派生素材缓存、取消/恢复、进度和重开草稿恢复机制。
3. 接入本地防抖、去频闪、运动模糊、降噪与补帧 Provider。
4. 将智能运镜、镜头追踪、智能裁剪建成“分析结果 -> 可编辑关键帧/轨迹”。
5. 最后接云端超清、消除、扩展和对口型，并补齐授权、上传、重试、计费与隐私状态。

每一步都应做真实视频 E2E：应用效果、播放预览、保存重开、导出、检查像素或媒体参数，并验证取消和缓存复用。只有 UI 开关、草稿字段或单元测试都不能证明功能完成。
